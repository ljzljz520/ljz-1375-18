# 古建筑修复对照档案 —— 系统设计说明

> 核心原则：**“把两张不同视点的照片缩放到相同宽高”不构成可比配准。**
> 每一次“对齐比较”都必须声明所使用的**配准模型**、给出**可量化的误差界限**，
> 不满足条件时系统强制退回**并排观察（side-by-side）**，不得宣称两图在几何上可比。
> 修复后**新增构件**只允许被遮罩标记，绝不允许通过扭曲把它“变成”旧结构的一部分。

---

## 1. 数据模型

```
Project(建筑/院落工程)
  └─ Pair(照片对照组)            # 组内版本不可变；编辑产生新版本
       ├─ photos: [oldPhoto, newPhoto]   # 旧照(历史影像) / 新照(现状或修复后)
       │     Photo { id, sha256, width, height,
       │             orientation(exif 1..8 归一化后的结果),
       │             crop{x,y,w,h}?,  sourceTransform[],      # 原图 -> 规范像
       │             capture{ date, camera, lens, focalMm?,
       │                      gps?, lighting, weather? },    # 摄影条件
       │             license{ holder, scope, expiresAt, status } }
       ├─ stage(阶段): BEFORE(残损) / WORKS(施工中) / AFTER(修复后)
       ├─ anchors: Anchor[]        # 结构锚点（可被两编辑同时操作 → 乐观锁）
       ├─ registration             # 配准结果，见 §2
       ├─ annotations: Annotation[]# 文字注释（含“未开放区域”常驻说明）
       ├─ tileSet                  # 服务端瓦片产物，见 §5
       └─ approval                 # 批准说明，见 §4
```

* **不可变版本**：`Pair` 每次编辑（换图、改锚点、改注释、重新配准）生成 `version+1`。
  已批准（approved）快照的 `groupId+version` 永久可解析，深链接不会失效。
* 任何前端视图（滑杆 / 并排 / 注释）渲染时都必须带上 `groupVersion`，三者引用同一版本。
* 摄影条件落库：焦距、拍摄时间、光照/天气等用于判断两视点几何/光度差异，写入比较元数据。

## 2. 配准模型与误差界限（领域核心）

### 2.1 允许的模型层级（按严格度递增）

| 级别 | 模型 | 自由度 | 适用 | 代码位置 |
|---|---|---|---|---|
| M0 | **并排观察** | 0 | 不满足任何配准条件时的**强制回退** | viewer `mode=side` |
| M1 | **平移+缩放+旋转（相似）** | 4 | 同机位、仅变焦/轻微转动 | `math.js similarity` |
| M2 | **仿射 Affine** | 6 | 同平面、正立面近似，允许剪切 | `math.js affineLeastSquares` |
| M3 | **人工对应点映射（TPS 薄板样条 / 分片）** | 2n | 立面有轻微起伏、需要逐点贴合 | `math.js tps`（≥6 点） |
| M4 | 透视单应 Homography | 8 | **仅当两图对应点近似共面**且 ≥4 点 | 仅在文档中给出限制 |

系统对 M1/M2/M3 实际计算并给误差；M4 只在满足共面前提时才可选，默认不放开自动解算。

### 2.2 仿射最小二乘与误差

旧照坐标 `u=(x,y)` → 新照坐标 `v=(x',y')`：

```
[ x'] = [a b tx] [x]
[ y']   [c d ty] [y]
```

用 n 对对应点构造 2n×6 正规方程，高斯消元求最小二乘解。
对每对对应点计算重投影误差 `e_i = ‖v_i − A u_i‖`（像素）。报告：

* `rms`：均方根误差 `sqrt(Σ e_i² / n)`
* `maxErr`：最大误差
* `relErr`：误差相对图像对角线的比例（跨分辨率可比）

### 2.3 可用性判定（error budget）

* 仿射最少 **3 个非共线**对应点；TPS 最少 **6** 个点。
* 阈值（可在服务端配置）：`relRms ≤ 0.5%` 且 `relMax ≤ 1.5%` 且**残差无空间聚集**。
* **不达标 → status=REJECTED，视图强制 M0 并排**，并显示各点残差供人工判断。
* 变换只在**已验证凸包（control hull）内部**声明有效；凸包外区域标记“外推区”，不声明对齐。
* 点数不足（缺基准点）、点共线、解算奇异：一律回退并排。

### 2.4 仿射 vs 人工对应点：能力与限制

* **仿射（M2）**：只能表达同一平面内的刚性+剪切；
  当两视点存在**透视汇聚**（斗拱/屋檐进深方向不可忽略）时，无法同时贴合近点与远点，
  残差会呈现系统性、方向性分布——这正是判定“仿射不适用”的信号。
* **人工对应点（M3/TPS）**：可吸收局部非刚性差异，贴合更好；
  但点数少、分布不均时会在控制点之间产生**过冲振荡**，且**遮挡区没有可信点**，
  TPS 在遮挡处的变形是无约束的外推，不能作为依据。
* **透视**：近大远小使单平面仿射失效；真透视需 Homography，前提仍是“对应点共面”。
  立面+屋面不共面时，任何单一全局模型都会扭曲其中一部分。
* **遮挡**：被脚手架/树木/后期构件遮挡处找不到同源点；遮罩区域不参与误差计算，也不做对齐声明。
* **结构变化（新增构件）**：新照里**修复后新增的斗拱、瓦面、彩画**在旧照中没有对应结构。
  这些区域用 `addedStructure` 遮罩标出并保持**新照原生形状**，
  **禁止**为了“对齐好看”而对其做形变，也禁止用仿射/TPS 把新增部分拉成旧结构。
  比较结论只能写“旧照此处缺失/残损，新照为新增构件”，不能写“旧结构恢复为……”。

## 3. 坐标迁移（裁切 / 方向变化）

规范像（canonical）= 经过 EXIF 方向归一化、并应用裁切后的坐标空间。所有标注都存规范坐标。

* 上传时记录 `sourceTransform`：`canonical = normalizeOrientation ∘ crop`（齐次 3×3 链）。
* 重新裁切/旋转/翻转图片时，对每个锚点/标注点**显式**施加同一变换：
  `p_canonical' = T_new · T_old⁻¹ · p_canonical`。
* **只有当迁移链完整、可逆、且迁移后点位仍落在新画面内**才自动迁移；否则该标注置
  `reviewStatus=PENDING`（待复核），在前端高亮，禁止纳入配准与批准。
* **图像翻转**：EXIF 方向/镜像变化若无法与现有 `sourceTransform` 唯一复合（例如手工镜像），
  一律不猜测，全部标注进入待复核，需人工确认左右关系后才能继续。

## 4. 批准与并发热点

* 批准对象是**不可变版本**：`approval { pairId, version, reviewer, note, approvedAt }`。
* 只有满足：两侧资源齐全且授权有效、配准 status=ACCEPTED（或明确声明 M0 并排）、
  无 PENDING 标注时，才可批准。批准后内容冻结，后续编辑另开版本。
* **锚点并发**：`Anchor.version` 乐观锁。两个编辑同时保存同一锚点时，后提交者携带旧版本号 →
  服务端返回 `409` 与服务器当前值，前端做差异合并，不允许静默覆盖。
* 瓦片产物与 pair 版本绑定（`tileSet.pairVersion`）；生成途中照片被替换：
  旧瓦片任务检测到 `pairVersion` 已推进即中止并标记 `SUPERSEDED`，绝不把旧瓦片挂到新版本。
* 批准快照独立于授权：**授权过期后原图可被拒绝下载，但已批准的比较结论、注释与瓦片缓存
  仍可按档案策略访问**（瓦片缓存的保留期随批准记录登记）。
* **验收一侧资源晚到**：只有一侧图时 pair 为 `INCOMPLETE`，只能标注、不能配准、不能批准；
  晚到侧上传后重新走配准与坐标检查。

## 5. 服务端瓦片（大图 / 资源限制）

* 上传只登记元数据与 sha256；瓦片由后台**任务队列**异步生成：金字塔 256px 瓦片（演示用 PNG）。
* **资源限制**：限制 `maxDecodePixels`（如 8000×8000 的解码预算）、并发任务数、单任务超时；
  超大图超出预算 → 任务 `REJECTED_RESOURCE_LIMIT`，要求先降采样/切片，服务器不同步爆内存。
* 演示实现逐瓦片按需解码、顺序生成，并在每片前检查 `pairVersion` 是否被替换（可中止）。
* 生成中：`PENDING → RUNNING → READY / FAILED / SUPERSEDED / REJECTED_RESOURCE_LIMIT`。
* 瓦片路径含内容哈希，版本不可变；前端 READY 后才从缩略图切换到瓦片金字塔。

---

## 6. 前端一致性与深链接

* URL：`#/pair/<id>/v/<n>?mode=slider|side&x=&y=&z=&layer=old,new,added,notes`
  深链接精确复现已批准版本的视图状态。
* 滑杆、并排、文字注释**全部从同一 `groupVersion` 拉取**，禁止各控件各自取“最新”。
* **未开放区域说明常驻**：`Annotation.pinnedRestricted=true` 的注释属于受限区域安全提示，
  任何图层开关都不得隐藏其文字（可在图上淡出定位点，但说明面板中始终保留）。
* 授权过期图层在图上显示占位与“授权已过期”角标，不影响常驻说明与已批准结论文字。
